# SAG-Benchmark v2.0.0 Release Notes

## Scope

This release candidate introduces the major v2 update of SAG-Benchmark for the SAG paper experiments. It combines the v2 search architecture, storage refactor, evaluation workflows, extraction updates, and public documentation.

The final `v2.0.0` tag and GitHub Release should be created after maintainer review, CI validation, and merge.

## Search strategies

The v2 benchmark exposes these public search strategies:

- `sag2`: the primary graph-based retrieval strategy with recall, expansion, and reranking stages.
- `atomic`: atomic retrieval with entity expansion.
- `vector`: pure vector retrieval baseline.
- `bm25`: Elasticsearch BM25 retrieval baseline.

SAG2 also supports the event-candidate-pool variant through `--sag2-scope`. This is an experimental variant of `sag2`, not a separate top-level strategy.

`MULTI_ES` remains available as a compatibility route, but it is isolated from the primary SAG2 implementation.

## Major changes

- Refactor the search pipeline into explicit recall, expansion, reranking, and orchestration stages.
- Add request-scoped event/entity candidate selection and stage-level diagnostics.
- Refactor storage interfaces and Elasticsearch backends behind a stable storage boundary.
- Add OceanBase storage profiles, initialization support, and vector-index configuration.
- Add retrieval evaluation, QA evaluation, and LLM-as-a-Judge workflows.
- Add compact extraction prompts and update upload/search benchmark workflows.
- Expand regression tests and update the architecture, development, search, and release documentation.
- Use the public `sag-benchmark` MLflow experiment default.

## Compatibility and migration

- Python 3.11 or newer is required.
- Existing imports, storage profiles, configuration keys, and benchmark commands should be reviewed before migrating from the previous version.
- Use the root `.env.example` as the public configuration template and keep real credentials in an untracked `.env`.
- `MULTI_ES` is retained for compatibility; new graph-search experiments should use `sag2`.
- Benchmark outputs and generated datasets are runtime artifacts and are not included in the source distribution.

## Validation

- `git diff --check` passes for the release branch.
- Full runtime tests should run in CI with Python 3.11 or newer and the required service dependencies.
